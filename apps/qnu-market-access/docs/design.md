# QNu Market Access Guide — local release

The source library has no existing application or application stack. Use Python's standard library for extraction, deterministic retrieval and a loopback HTTP server, plus semantic HTML, CSS and JavaScript. No external services or runtime installation required. No production identity provider has been selected.

Import all six XLSX sheets and the internal CSV into an immutable, hash-addressed private snapshot. Preserve every populated cell, merges, fills, headings and original values; normalize requirements, gap assertions, questions, sources, modules and certification assertions separately. Reject changed schemas, formulas or unresolved source IDs. Revised imports stage by default; a local reviewer explicitly activates a snapshot. Partner approvals bind to a snapshot and expire when it changes.

Apply country, regional and India export scopes together, with exact-text deduplication and every contributing cell retained. The workbook's form-factor and segment assumptions remain source assertions. Conditions are shown explicitly; uncertain applicability stays visible. QShield shared gates, selected modules, SaaS cloud clauses, accompanying QRNG and referenced Vault buyer expectations are combined without transferring certifications.

The local demo role switch creates server-side sessions. It is deliberately not authentication. The server binds only to loopback, rejects unexpected hosts and cross-origin mutations, uses CSRF tokens and serves only an explicit public-file allowlist. Partner filtering occurs before serialization, evidence and export generation. Raw workbook, CSV, gaps, roadmap and open-question records stay internal. Partner requirements are a conservative projection; mixed internal text is withheld. Administrator invitations are local drafts and send no messages. Administrators can explicitly approve a single statement locally, after reviewing evidence and scope; automated delivery never performs this approval.

UI: compact top navigation, a 248px context panel, expandable applicability controls, a concise conditional summary, requirement list, actions, certification claims, source records and print briefs. Country and product use explicit searchable comboboxes; Customer type uses the same rendering with a fixed list: clicking shows all choices, typing filters, and Arrow keys/Enter/Escape support keyboard selection. Dark QNu reference palette with orange action controls and lavender product labels; 13px body text, 32px controls and inline counts. Source dates and assumptions are available in a collapsed disclosure rather than repeated in the working view. Technical cell/CSV references, original wording and missing-date metadata are available through a Source details control; reader-facing prose uses plain source descriptions. Print briefs also collapse these details by default. Responsive mobile controls use two columns before the results. No remote fonts or telemetry. Print briefs are generated on the server under the current session role and contain sources and qualifications.

Validation: independent cell reconciliation, every sheet and source ID, representative bundles/modules/regions/export/missing cases, roadmap conflicts, direct API/evidence/download/export restriction tests, spoofed roles, CSRF and local-host controls; running desktop/mobile browser review and PDF rendering.

Identical date-conflict messages merge their evidence references into one record. Actions state the common applicability instruction once and list the mandatory checks without repeated boilerplate. Unspecified responsibility remains blank. Dataset hashes are reserved for governance and source details.
